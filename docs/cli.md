# CLI

UI と同じことは端末からもできる。自動化したい場合や、UI が使えない場合に。
ただし **DLC の重ね合わせ・パッチの実行・削除は UI にしか無い**（[DLC とパッチ](dlc.md)）。

| サブコマンド | 内容 |
|---|---|
| `check` | 環境とセッションを確認する（UI の「状態・ログイン」タブと同じ内容） |
| `login` | ログイン手順を表示する |
| `init` | `config.json` を作成する |
| `serve` | ローカル Web UI を起動する |
| `list` | 購入済みライブラリを一覧する |
| `download` | 作品をダウンロードして展開する |
| `adopt` | 手作業で展開済みのフォルダを管理下に取り込む |
| `steam` | 導入済みゲームを Steam に登録・解除する |

全体に効くオプション: `--config <path>`（設定ファイルの場所）、
`-y` / `--yes`（プロジェクト外への書き込み確認を省略）、`--version`。

```bash
python3 -m dlsite_deck check
```

`serve` は `--host`（既定 `127.0.0.1`）、`--port`（既定 `8765`）、
`--no-browser`（ブラウザを自動で開かない）を取る。

```bash
python3 -m dlsite_deck list --category manga
```

指定できるカテゴリ: `game` `manga` `cg` `novel` `voice` `music` `video` `tool` `other`
（既定はゲームのみ、`--all` で全部）。`--updates` / `--installed` / `--missing` で
更新があるもの・導入済み・未取得だけに絞れる。

## ダウンロードと展開

```bash
python3 -m dlsite_deck download RJ123456
```

```bash
python3 -m dlsite_deck download --all
```

```bash
python3 -m dlsite_deck download --updates
```

中断しても `.part` から再開する。オプション:

| | |
|---|---|
| `--dry-run` | 対象を表示するだけで実行しない |
| `--no-extract` | 展開せずダウンロードのみ行う |
| `--keep-archives` | 展開後もアーカイブを残す（設定の `delete_archives` より優先） |
| `--force` | 導入済みでも取り直す |
| `--install-dir <path>` | 展開先。設定した一覧のどれかであること |

## 既に手作業で展開してあるゲームの取り込み

ツールを使う前に自分で展開したゲーム群を、ダウンロードし直さずに管理下へ入れられる。
対応表（フォルダと作品 ID の組）を渡すと、`state.json` に記録するだけで
**ファイルには一切触れない**。

```bash
python3 -m dlsite_deck adopt mapping.json --dry-run
```

対応表の形式:

```json
[{"directory": "/run/media/deck/SD/extgames/some-game", "work_id": "RJ123456"}]
```

対応表は手で書くか、自分で調査スクリプトを用意する。作者の環境で使った移行用
スクリプトは、その環境の一度きりの作業に強く依存していたため公開していない。
フォルダ内に残った作品 ID、Steam に登録したタイトル、フォルダ名のローマ字表記を
突き合わせて候補を出す。

> フォルダ内の readme に**他作品の宣伝として作品 ID が書かれている**ことがあるため、
> ID だけを根拠に確定してはいけない。実際、3.4GiB のゲームが readme の宣伝 ID により
> 0.2GiB の別作品と誤判定された。名前やサイズと突き合わせて裏を取ること。

## Steam への登録

**Steam を終了してから**実行する（起動中に `shortcuts.vdf` を書き換えても Steam 終了時に上書きされる）。
Steam の起動判定は Linux / Windows の両方で行い、起動中なら中断する。

実行ファイルと登録名を対話的に選ぶ:

```bash
python3 -m dlsite_deck steam RJ123456 --choose
```

指定して登録する:

```bash
python3 -m dlsite_deck steam RJ123456 --exe "/path/to/Game.exe" --title "好きな名前"
```

まとめて既定のまま登録する:

```bash
python3 -m dlsite_deck steam
```

登録を解除する:

```bash
python3 -m dlsite_deck steam RJ123456 --remove
```

そのほかのオプション: `--dry-run`（対象を表示するだけ）、`--no-images`（表紙・背景を
設定しない）、`--images-only`（`shortcuts.vdf` は変更せず、既存の登録に画像だけを
設定する。Steam 側で別名を付けてあるゲーム向け）。

解除すると `shortcuts.vdf` のエントリに加えて、このツールが置いた表紙・背景・ロゴも
削除する。**Steam のライブラリ画面から直接削除した場合は画像が残る**ので、
片付けまで任せたい場合はこのツールから解除すること。

書き換え前に `shortcuts.vdf.bak-<日時>` を残す。既に同名の登録がある場合は
識別と起動に関わる項目だけを更新し、`LaunchOptions` や `icon`、`sortas` など
Steam 上で設定した内容には触れない。

`userdata` は自動検出する（Windows ではレジストリの `SteamPath` も見る）。
検出できない場合は `config.json` の `steam_userdata_dir` で明示する。

## Proton の自動割り当て

DLsite のゲームは Windows 向けなので、登録と同時に互換ツール（Proton）を割り当てる。
既定は **Proton Experimental**。設定画面の「登録時に割り当てる Proton」で、
インストール済みの Proton から選べる（公式版と `compatibilitytools.d` に置いた
GE-Proton などの両方を検出する）。

**既に割り当てがあるゲームは変更しない。** ゲームごとに使い分けている設定を
上書きしないため。未割り当てのものだけを埋める。

割り当ては `<steam>/config/config.vdf` の `CompatToolMapping` に記録される。
このファイルには利用者の設定が大量に入っているので、全体を書き戻さず該当箇所だけを
差し替え、書き込み前に控えを作る。

> 設定に書く名前はフォルダ名と綴りが違う。`Proton 8.0` は `proton_8`、
> `Proton 5.13` は `proton_513`、`Proton - Experimental` は `proton_experimental`。
> `compatibilitytools.d` に置いたものはフォルダ名がそのまま名前になる。

## Proton 設定タブ（後から変更する）

**Proton 設定** タブに、登録済みゲームの一覧と現在割り当てられている Proton が
並ぶ。行のプルダウンから選び直すとその場で変更される。タイトル・作品 ID での
絞り込みと、割り当て済み／未設定での絞り込みができる。

**並べ替え**はタイトル順と Proton 順の 2 通り（昇順・降順）。Proton 順のときは
同じ Proton の中をタイトル順で並べ、未設定のものは向きに関わらず末尾に置く。
ライブラリ画面の並べ替えと同じ規則。

**Steam の設定画面から変更するのと同じ効果。** 書き込む先も形も同じで、実機の
`config.vdf` にあった既存の割り当ては、Steam の設定画面から設定したものもこのツールが
書いたものも、すべて `name` / `config` / `priority` の同一の形をしていた。

> **Steam を終了してから操作すること。** Steam は `config.vdf` を抱えたまま動き、
> 終了時に書き戻す。起動中に書き換えても捨てられるため、起動中は変更を受け付けず
> 警告を出す（プルダウンも操作できなくなる）。

一覧に無い名前が割り当てられている場合（`compatibilitytools.d` から消した
GE-Proton など）は、その名前を赤字で表示して選択肢にも残す。気付かずに
別の版へ変えてしまわないようにするため。

「未起動」と付いているゲームはまだプレフィックスが作られていない。
プレフィックスは Steam から一度起動すると作られる。

## 起動オプション（日本語の文字化け対策）

**SteamOS には `ja_JP.UTF-8` ロケールが入っていない。** そのため日本語のゲームは
画面表示もファイル名も文字化けすることがある。Steam の起動オプションでロケールを
渡すと直る。

設定の **「既定の起動オプション」** に書いておくと、登録画面の初期値になる。
登録時にその場で変更もできる。

ロケールの用意の仕方は環境によるので**既定は空**にしてある。よく使われるのは
ロケールを自前で用意して `LOCPATH` を差し込む方法:

```
LANG=ja_JP.UTF-8 ~/locales/run.sh  %command%
```

`%command%` は Steam が実際の起動コマンドに置き換える。

既に Steam 側で設定してあるゲームを登録し直す場合、**登録画面には現在の設定が
初期値として出る**。そのまま登録すれば維持され、書き換えれば反映される。
ツールから指示しない限り `LaunchOptions` には触れないので、Steam 上で手を加えた
内容が黙って消えることはない。

## ライブラリの表紙・背景

登録と同時に、DLsite のストアページ 1 枚目の画像（`work_files.main`）を
ライブラリの画像として設定する。Steam は非 Steam ゲームの画像を
`userdata/<id>/config/grid/` に AppID 名のファイルで持つ仕様なので、そこに置く。
exe と同じフォルダに画像を置いて認識させる仕組みは Steam には無い。

| ファイル名 | 用途 | Steam が想定する寸法 |
|---|---|---|
| `<AppID>p.jpg` | ライブラリの表紙（縦長） | 600x900 |
| `<AppID>_hero.jpg` | 背景 | 1920x620 |
| `<AppID>.jpg` | 横長カプセル | 460x215 |
| `<AppID>_logo.png` | ロゴ（背景に重ねて表示） | 任意・透過 PNG |

`<AppID>` は `shortcuts.vdf` の `appid` を**符号なし**で表した値。

**DLsite の画像は 560x420（4:3）**で、上のどの寸法とも比率が合わない。

### 縦長カバーにタイトルを載せる

**Steam のストア製品はカバーにタイトルロゴが焼き込まれているが、DLsite の画像には
それが無い。** そのままではライブラリの一覧で**どれがどのゲームか分からない**ので、
縦長カバーだけは作り直す（`steam_cover_title`）。

1. 作品画像を**中心から 2:3 に切り出す**（560x420 → 中央の 280x420 を使う）
2. 600x900 に拡大する
3. 下部に**白い半透明の下地**を敷き、その上にタイトルを**白文字・太い黒縁**で描く
4. 文字の大きさは**横に 10 文字（全角換算）入る**ように決め、そこで折り返す

タイトルが長くて行数が増えるときは、カバーが文字で埋まらないよう自動で縮める。
半角文字は全角の半分として数えるので、英語のタイトルは 1 行に 20 文字入る。

**このカバーは縦長スロットにしか使わない。** 横長カプセル（460x215）と背景
（1920x620）は比率が違うので、これまでどおり元の画像をそのまま置く。

### ロゴ

`steam_logo_source` で 3 通りから選ぶ。

| 値 | |
|---|---|
| `title`（既定） | **タイトルだけの透過 PNG**。折り返さない 1 行で、カバーと同じ白文字・黒縁・白い下地 |
| `exe` | **exe に埋め込まれたアイコンのうち一番大きなもの**。PE のリソースを解析して PNG に変換する（PE 解析も PNG 書き出しも依存を増やさないため自前）。対応形式は PNG 埋め込みと DIB の 32/24/8/4/1bpp で、DIB は AND マスクを透過に変換する。アイコンが無い exe では飛ばす |
| `none` | 設定しない |

### ストア画像の控え

取得したストア画像は、作品フォルダに **`.dlsite-store-image.jpg`**（PNG なら `.png`）
として残す。カバーを作り直すたびに DLsite から取り直すのは無駄で、セッションが
切れていればそもそも取れないため。

- **作り直しは通常オフラインで済む。** 実機での実測では、2 回目以降は通信を一切せず
  3 件あたり 1.1 秒だった
- 隠しファイルなので普段は見えない。作品を削除すればフォルダごと消える
- 壊れていたり形式が違うものは無視して、取り直しに戻る

### カバーを作り直す

設定を切り替えたあと、**登録し直さずに反映させる**ための操作。
設定タブの **「カバーを作り直す」** ボタンから実行する。

登録済みのゲームすべてについて、表紙・背景・ロゴを**今の設定どおりに突き合わせる**。
作るだけでなく、**使わなくなった画像は引き上げる**:

| 変えた設定 | 起きること |
|---|---|
| `steam_cover_title` を `false` に | タイトル入りカバーを消し、元の画像を置き直す |
| `steam_logo_source` を `none` に | 置いてあるロゴを消す |
| `steam_grid_slots` からスロットを外す | そのスロットの画像を消す |
| `steam_grid_images` を `false` に | 登録済みゲームの画像をすべて消す |

設定を戻してもう一度押せば**元に戻る**（片道にならない）。
**別環境と重複しているエントリには触らない**（名前で照合するため書き換えてしまう）。

**Steam を起動し直すまで表示は変わらない。** Steam は起動中に読んだ画像を抱えている。
ファイルを書くこと自体は起動中でも安全なので、操作は塞いでいない。

CLI からは同じことを `--images-only` で行える。

```bash
python3 -m dlsite_deck steam --images-only
```

### 描画に使うもの

タイトルの描画は **`rsvg-convert`** に任せている。SteamOS に最初から入っている
コマンドで、フォントの選択（Noto Sans CJK JP）と日本語の字形はこれが面倒を見る。
標準ライブラリだけでは TrueType の字形を起こせないため、ここだけ外部に頼っている。

**このコマンドが無い環境では静かに諦め、元の画像をそのまま置く**（登録自体は成立する）。
Windows の開発機には無いので、タイトル入りのカバーは実機でのみ作られる。

### 既定は環境で決まる

`steam_cover_title` の既定は固定値ではなく、**その環境で描けるかどうかで決まる**。

| | |
|---|---|
| `rsvg-convert` と日本語フォントが揃っている | 既定 **ON** |
| どちらかが欠けている | 既定 **OFF** |

揃っていない環境で有効にしても、**タイトルが豆腐（□）で並んだカバー**ができるだけで
嬉しくないため。`config.json` に書いてあればそちらが優先される。

フォントの有無は **fontconfig に尋ねる**（`fc-list :lang=ja`）。描いて見比べる手は
使えない。字形が無い文字は豆腐になるが、**最近の豆腐は枠の中に符号位置の 16 進を
並べた絵**なので、文字ごとに違う絵になり区別が付かない（実機で確認済み）。
`fc-list` が無い環境では判断できないので、描ける前提で通す。

**OFF から ON に切り替えたときは、描けない環境なら警告を出す。** 設定画面では
チェックしたその場に理由が出て、保存時にも出る。**保存は止めない**（別の環境に
持っていけば効くため）。

### 画像をやめる

気になる場合は `steam_cover_title` を `false` にする（切り抜きもタイトルも行わず、
元の画像をそのまま置く）。`steam_grid_slots` から `"cover"` を外す、
`steam_grid_images` を `false` にして SteamGridDB などの画像を手で設定する、
という手もある。

```bash
python3 -m dlsite_deck steam RJ123456 --no-images
```
