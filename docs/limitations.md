# 既知の制限

## ログインとブラウザ

- **Chromium 系のブラウザ（Chrome、Edge など）には対応していません。**
  これらのブラウザは Cookie を OS の機能で暗号化していて、Python の標準ライブラリだけでは読み取れません。
  Firefox を使うか、設定の `cookie_source` を `manual` にして、書き出した Cookie のファイルを読み込ませてください。
- **非公式の API を使っています。** DLsite 側の変更によって、予告なく動かなくなることがあります。

## セキュリティ

Web UI は同じ端末（`127.0.0.1`）からしか接続できませんが、同じ端末で動く他の Web サイトやプログラムは接続できます。そのため、次の対策を入れています。

| 対策 | 防ぐもの |
|---|---|
| 起動ごとに合言葉を作り、ツールが開く URL の `#t=…` でだけ渡す | 合言葉を知らない相手からの操作。`#` の後ろはサーバーに送られないので、画面を取得しても合言葉は分かりません |
| 名前（ドメイン）経由の接続を断る | DNS リバインディング（攻撃者のドメインを途中で `127.0.0.1` に向け直す手口） |
| 他のサイトから送られた要求を断る | 別のサイトを開いたときに、裏でツールを操作されること |
| 場所やプログラムを指す設定と、起動オプションを画面から変えられないようにする。インストール先は、端末で承認した場所の中からだけ選べるようにする | 万一合言葉が漏れた場合に、ツールを使って任意のプログラムを実行されたり、ゲームを別の場所にダウンロードされたりすること |
| DLsite とは HTTPS でしか通信しない。`http://` の URL やリダイレクトは `https://` に置き換え、`file:` などは開かない | ログイン情報が暗号化されずに流れること。DLsite のログインを保つ Cookie（`__DLsite_SID` など）は、DLsite 側の設定で HTTPS 限定になっていないため |
| 展開した作品の中で、作品ディレクトリの外を指すシンボリックリンクを取り除く。DLC の重ね合わせと書き戻しでは、外を指すリンクを経由する場合に中止する | 作品に仕込まれたリンクを辿って、作品ディレクトリの外のファイルを読み書きされること |
| 画面を閉じてしばらくたつと、ツールが自動で終了する | デスクトップモードで、使っていないツールが裏で待ち受けを開けたままにしていること |
| 何も送らない接続は 1 分で切り、同時に開ける接続を 32 本までにする | 接続を開いたまま居座り、ツールのメモリを食いつぶしたり、終了できなくしたりすること |

**防げないもの**もあります。

- **自分と同じユーザーで動く、サンドボックスの外のプログラム**：ブラウザの起動引数や履歴から合言葉を読めます。ただし、そうしたプログラムはこのツールを使わなくても、Firefox の Cookie を直接読んで DLsite にアクセスしたり、導入済みのゲームのファイルを読んだりできます。ツールを止めても危険は変わらないので、信頼できないプログラムを動かさないことが唯一の対策です。
  **Steam のゲームもこれに当たります。** Proton のゲームも含めて `deck` ユーザーとして動き、Steam がゲームを入れる隔離環境（Steam Linux Runtime）もホームディレクトリとネットワークは共有しています。悪意のあるゲームや Mod は、このツールがなくても DLsite のログイン状態を盗めます。心配な場合は、使い終わったら Firefox で DLsite からログアウトしてください。
- **`--host` で他の端末に開いた場合の通信**：他の端末からの操作にも合言葉が必要ですが、通信は暗号化されないので、同じネットワークで盗み見られると合言葉ごと読まれます。既定の `127.0.0.1` のまま使ってください。
- **ツールを使っていること**：待ち受けは、合言葉がなくても応答のヘッダーと画面のタイトルで名乗ります。ポートにつなげるプログラムなら、DLsite のツールを使っていることは分かります。
- **合言葉が漏れた場合の購入履歴**：上の対策で任意のプログラムの実行は防げますが、購入済み作品の一覧を読むことや、ダウンロード・削除を実行すること、承認済みの場所の中でインストール先を入れ替えることはできてしまいます。

> [!NOTE]
> 以前の版では、画面で設定を保存すると、プロジェクト外の場所が自動で承認済みになっていました。
> `config.json` の `acknowledged_paths` に見覚えのない場所がないか、一度確認することをおすすめします。

Flatpak のアプリのように、ホームディレクトリを読めずネットワークにだけ出られるプログラムは、合言葉を得られないので操作できません。

## 作品の取得

- **漢字のタイトルをローマ字にするには pykakasi が必要です。** 詳しくは [導入 — pykakasi が必要な理由](install.md#pykakasi-が必要な理由) をご覧ください。
- **一部の購入作品は取得できません。** 作者の環境では、数件の作品（いずれも作品 ID が `VJ` で始まる商業タイトル）で、作品情報もダウンロードも取得できませんでした。
  該当する作品 ID は、`list` コマンドの最後に表示します。
- **分割 RAR の展開には外部のコマンドが必要です。** `7z`・`unrar`・`bsdtar` などがない環境では展開できません（SteamOS には最初から入っています）。
  なお、`bsdtar` しかない環境で分割 RAR を展開できるかは確認していません。SteamDeck でも Ubuntu でも、先に `7z` などが見つかるためです。

## 更新の確認

- **更新があるかどうかは、DLsite の更新日で判断しています。**
  DLsite の API にはバージョン番号がないため、導入したときより新しい更新日になっていれば「更新あり」とします。
  日付は日本時間で表示します（DLsite は日本時間の 0 時を UTC で返すので、そのまま表示すると 1 日ずれます）。
- **更新日を返さない作品があります。** 作者の環境では約 4 割がそうでした。
  その場合はタイトルに含まれる版の表記（`Ver.1.3.2` など）も見ますが、該当する作品にはそうした表記がなく、実際には役に立っていません。
  このような作品は更新を確認できないので、一覧では「更新日なし」と導入した日時だけを表示します。

## Steam の表紙

- **表紙にタイトルを入れるには `rsvg-convert` が必要です。** Python の標準ライブラリだけでは、フォントから文字を描けないためです。
  SteamOS には最初から入っていますが、Windows にはないので、元の画像をそのまま使います（[描画に使うもの](cli.md#描画に使うもの)）。
  その他の Linux デスクトップでは、インストールすれば使えます（[他の環境で使う](platforms.md)）。
- **タイトル入りの表紙は、元の画像の左右を切り捨てます。** 560×420 の画像の中央を縦横比 2:3 で切り出すと 280×420 になり、これを 600×900 に約 2.1 倍に拡大するので、画像がぼやけます。
  DLsite からはこれより大きな画像を取得できないため、画質はこれ以上良くできません。

## DLC

- **書き戻せるのは、上書きされたファイルだけです。** DLC によって新しく追加されたファイルは残ります。
  退避したファイルだけではどれが DLC のファイルか判断できず、誤って必要なファイルまで消してしまうおそれがあるためです（[DLC とパッチ — 取り消す](dlc.md#取り消す)）。

## コントローラ設定を扱えない理由

「登録したゲームに標準のコントローラ設定を割り当てる」機能は、実装できません。Steam の仕組み上、外部から安全に書き込む方法がないためです。

標準の設定（テンプレート）自体は `~/.steam/steam/controller_base/templates/` にあります（SteamDeck 向けの `controller_neptune_gamepad`、`controller_neptune_mouse`、`controller_neptune_wasd` など 8 種類）。
問題は、どのゲームにどの設定を使うかという**割り当て**の保存場所です。SteamDeck で調べた結果は次のとおりです。

| 調べた場所 | 結果 |
|---|---|
| `userdata/<ID>/config/controller_configs/apps/` | 空で、割り当ての記録はありませんでした |
| `localconfig.vdf` の該当する AppID | 記録はありませんでした |
| `localconfig.vdf` の `controller_config` | ゲーム名と使用時間だけでした |
| `userdata/<ID>/241100/remote/` | Big Picture 用など、少しのファイルだけでした |
| `userdata/<ID>/241100/ac/GameInstall/.../config/` | 空のディレクトリが並んでいるだけでした |

決め手になったのは `241100/remotecache.vdf` で、Steam Input の設定 135 件が Steam Cloud で同期されていました。
`controller_neptune` という文字列も `ugcmsgcache/*.cachedmsg` に含まれていて、コントローラの設定はユーザー作成コンテンツ（UGC）としてサーバー側で管理されていることが分かりました。

`shortcuts.vdf` や `config.vdf` は Steam が端末に保存している本体なので、Steam を終了してから書き換えれば反映されます。コントローラの設定はそうではありません。

- 割り当ての本体はサーバー側にあるので、端末で書き換えても、次に Steam を起動したときの同期で上書きされます。
- `configset_*.vdf` はコントローラの種類ごとの設定で、ゲームごとの割り当てではありません。
- 非 Steam ゲームには対応する設定情報がないので、Steam が既定のテンプレートを自動で割り当てています。

つまり、実装しても効果のない設定項目にしかならないので、あえて実装していません。

**コントローラの設定はゲームモードで行ってください。** ライブラリでゲームを選び、コントローラのアイコンから使いたいテンプレートを選びます。一度選べばクラウドに保存され、次からもその設定が使われます。

## Windows で Web UI を使うときの注意

作者の Windows 環境では、Web UI への接続が約 1 割の割合で切断される現象がありました（`WinError 10053`「確立された接続がホスト コンピューターのソフトウェアによって中止されました」）。
Python の標準ライブラリだけで作った最小限のサーバーでも同じことが起きたので、ツールの問題ではなく、その環境のセキュリティソフトが通信を検査していることが原因だと考えています。

これに備えて、次の対策を入れています。SteamOS では通常は起きませんが、害はないので常に有効にしています。

- 4 KB を超える応答は gzip で圧縮して送ります（作品の一覧は 82 KB から 12 KB になります）。
- 応答は 16 KB ずつに分けて送ります。
- 画面側では、通信そのものに失敗した場合に限り、3 回まで再試行します。
- 接続が切れたあとに、エラーの応答を送ろうとして二重に失敗しないようにしています。
