# 既知の制限

- **Chromium 系ブラウザに未対応。** Cookie が OS のキーリングで暗号化されており
  標準ライブラリだけでは復号できない。Firefox を使うか、`cookie_source` を
  `manual` にしてエクスポートした Cookie ファイルを読ませる。
- **漢字タイトルは pykakasi が無いとローマ字化できない。** 詳細は [導入 — pykakasi について](install.md#pykakasi-について)。
- **一部の購入作品は Play API が扱わない。** 実環境では数件
  （いずれも `VJ` の商業タイトル）がメタデータもダウンロードも 404 だった。
  `list` の末尾に該当 ID を表示する。
- **更新の判定は `upgrade_date` に頼っている。** API に版番号のフィールドは無い
  (Play API 38 キー・公開 API 255 キーを全走査して確認)。導入時より新しい
  `upgrade_date` が来ていれば更新とみなす。日付は日本時間で表示する
  (DLsite は JST 0 時を UTC 15:00 として返すため、そのまま出すと 1 日ずれる)。
- **`upgrade_date` を返さない作品がある。** 実ライブラリでは **4 割ほど**。
  予備としてタイトル内の版表記 (`Ver.1.3.2` など) を見るが、実測では該当する作品に
  版表記のあるものは無く、**現状は効いていない**。該当作品は更新を検出できないので、
  一覧では「更新日なし」と導入日時だけを出す。
- **DLC の書き戻しは上書きされた分だけ。** DLC が新しく追加したファイルは残る。
  退避の中身だけではどれが DLC 由来か区別できず、消しすぎる害のほうが大きいため
  （[DLC とパッチ](dlc.md#取り消す)）。
- **カバーへのタイトル描画は `rsvg-convert` 頼み。** 標準ライブラリだけでは TrueType の
  字形を起こせないため。SteamOS には標準で入っているが、Windows の開発機には無いので、
  そちらでは元の画像がそのまま置かれる（[CLI](cli.md#描画に使うもの)）。
  他の Linux デスクトップでは入れれば使える（[SteamDeck 以外の環境](platforms.md)）。
- **タイトル入りカバーは元画像の左右半分を捨てる。** 560x420 を中心から 2:3 に
  切り出すと 280x420 になり、600x900 へ 2.1 倍に拡大するぶん眠くなる。
  DLsite がこれより大きい画像を返さないため、解像度はこれ以上上げられない。
- **分割 RAR の展開は外部コマンド頼み。** `bsdtar` などが無い環境では展開できない。
- **コントローラ設定は変更できない（Steam の作りによる制限）。** 下記参照。
- 非公式 API のため、DLsite 側の変更で予告なく壊れうる。

## コントローラ設定を扱えない理由

「登録したゲームに標準テンプレートを割り当てる」機能は**実装できない**。
Steam の作り上、外部から安全に書き込む手段が無いため。

標準テンプレート自体は `~/.steam/steam/controller_base/templates/` に置かれている
（Steam Deck 向けは `controller_neptune_gamepad`、`controller_neptune_mouse`、
`controller_neptune_wasd` など 8 種）。問題は**どのゲームがどれを使うかという
割り当ての置き場**で、実機を調べた結果は次のとおり:

| 調べた場所 | 結果 |
|---|---|
| `userdata/<id>/config/controller_configs/apps/` | 空。割り当ての記録なし |
| `localconfig.vdf` の該当 AppID | 記録なし |
| `localconfig.vdf` の `controller_config` | ゲーム名と `usetime` のみ |
| `userdata/<id>/241100/remote/` | Big Picture 用など少数のみ |
| `userdata/<id>/241100/ac/GameInstall/.../config/` | 空ディレクトリが並ぶだけ |

決め手は `241100/remotecache.vdf` で、**Steam Input の設定 135 件が Steam Cloud で
同期**されていた。`controller_neptune` の文字列も `ugcmsgcache/*.cachedmsg` にあり、
コントローラ設定は **UGC としてサーバー側で管理されている**。

`shortcuts.vdf` や `config.vdf` は Steam がローカルに持つ実体なので、Steam を終了して
書き換えれば反映される。コントローラ設定はそうではない:

- 割り当ての本体はクラウド側にあり、ローカルに書いても**次回起動時の同期で上書きされる**
- `configset_*.vdf` は**コントローラ種別ごと**の設定で、ゲーム別の割り当てではない
- 非 Steam ゲームには対応マニフェストが無いため、Steam が既定テンプレートを自動で当てている

つまり「効かない設定項目」しか作れないので、あえて実装していない。

**設定したい場合はゲームモードで行う。** ライブラリでゲームを選び、コントローラの
アイコンから使いたいテンプレートを選ぶ。一度選べばクラウドに保存され、以後は維持される。

## Windows で Web UI を使うときの注意

開発機（Windows）で `serve` を試したところ、loopback への HTTP 接続が
**約 1 割の頻度で外部から切断される**現象があった（`WinError 10053`
「確立された接続がホスト コンピューターのソフトウェアによって中止されました」）。
標準ライブラリだけの最小構成のサーバーでも再現するため、ツール側の不具合ではなく、
その環境で動いているセキュリティ製品が loopback を検査していることによるものと考えられる。

これを踏まえて次の対策を入れてある。SteamOS では通常起きない想定だが、
いずれも害はないのでそのまま有効にしている。

- 4KB を超える応答は gzip で送る（一覧は 82KB → 12KB になる）
- 応答は 16KB ずつに分けて書く
- 画面側は通信そのものが失敗した場合に限り 3 回までやり直す
- 接続が切れた後にエラー応答を書こうとして二重に落ちないようにする
