# 検証状況

実際の DLsite アカウント（購入作品は約 200 件）と、SteamDeck の実機などで確認した内容をまとめています。
Steam のファイルを書き換える確認は、特に記載がない限り、実際のファイルを複製した環境で行いました。

## DLsite との通信

| 項目 | 結果 |
|---|---|
| Cookie の読み取りとログイン | 実際のアカウントで確認しました。購入作品をすべて取得できました |
| 作品の一覧と作品情報 | 約 200 件の実データで確認しました |
| ダウンロード方法の判定 | 10 件の作品で確認しました（すべて通常のダウンロード） |
| シリアルコードが必要な作品 | **未確認です**（全体の 1 割弱で、どれも数百 MB 以上あるため） |

購入作品のダウンロード方法をすべて調べたところ、大半は通常のダウンロードで、シリアルコードが必要なものが 1 割弱、分割 RAR は 1 件だけでした。分割 RAR は現在ではほとんど使われていません。

## ダウンロードと展開

| 項目 | 結果 |
|---|---|
| ZIP 1 つの作品 | 2 件で確認しました。ダウンロード、展開、ディレクトリの整理、exe の検出、記録まで問題ありませんでした |
| 分割 RAR の作品 | 1 件（2.76 GB、3 分割）で確認しました。39 ファイル・2.6 GB を展開し、設定ツール（`Config.exe`）ではなく本体（`Game.exe`）を正しく選べました |
| Linux での展開 | Windows で作られた ZIP の `\` 区切りのパス、大文字・小文字だけが違うファイル名、Linux でしか使えない文字を含むファイル名、実行権限の維持を確認しました |
| インストール先の切り替え | 2 つ目のインストール先を追加して 1 件ダウンロードし、選んだ場所に展開されること、展開後にアーカイブ（37.3 MiB）が削除されることを確認しました |

## Steam への登録

| 項目 | 結果 |
|---|---|
| `shortcuts.vdf` の読み書き | 既存の登録や日本語の名前を含む実際のファイルで確認しました。読み込んで書き出した内容が 1 バイトも変わらないこと、追加、繰り返し実行、解除を確認しました |
| Web UI からの登録 | 実際の `shortcuts.vdf` に 2 件登録して確認しました。既存の登録は変わらず、日本語と全角スペースを含むパスも正しく記録されました。同じ作品を登録し直しても重複せず、名前を変えた場合は古い名前の登録が残りませんでした |
| 登録の解除 | コマンドラインと Web UI の両方で確認しました。登録の削除、その作品の画像 4 枚の削除、他の作品の画像が残ること、記録が未登録に戻ることを確認しました |
| 別の環境の登録との区別 | Windows と SteamDeck の両方で、自分の環境の登録だけが数えられていることを確認しました。Windows 形式の登録を混ぜたファイルでも、正しく除外され、操作が止められることを確認しました |
| Steam の終了（SteamDeck） | デスクトップモードで確認しました。約 23 秒で終了し、操作できる状態に戻りました。`shortcuts.vdf` は壊れませんでした |
| Steam の終了（Ubuntu） | ログイン済みの Steam は 4 秒で終了しました。サインイン画面のままの Steam は、90 秒待っても終了しませんでした |
| インストールしたばかりの Steam への Proton の割り当て | Ubuntu に新しくインストールした Steam で確認しました。`CompatToolMapping` がない状態から作成でき、既存の設定が残ることを確認しました。SteamDeck ではすでに割り当てがあったため、この環境で初めて見つかった不具合です |

## 表紙とロゴ

| 項目 | 結果 |
|---|---|
| 表紙と背景の設定 | 2 件・6 枚で確認しました。正しいファイル名で置かれ、自分で設定した画像には触れないことを確認しました |
| タイトル入りの表紙 | SteamDeck で、短い・中くらい・長い（日本語と英語が混ざった）タイトルの 3 件を確認しました。600×900 になること、日本語が正しく描かれること、長いタイトルが 4 行に折り返されて小さくなることを目で見て確認しました。ロゴは 1 行のまま横に伸びる透過 PNG になりました |

| 描けるかどうかの判定 | SteamDeck で、通常は「描ける」と判定されることを確認しました。日本語フォントを外した状態では「描けない」と判定され、既定がオフになり、理由が表示されることを確認しました |
| exe のアイコン | 3 種類の exe で確認しました。色、上下の向き、透過が正しいことを目で見て確認しました |

## Web UI

| 項目 | 結果 |
|---|---|
| ライブラリ | 約 200 件の実データで確認しました。カテゴリの切り替え、exe が複数ある作品での選択、DLsite のタイトルの初期表示を確認しました |
| 状態・ログイン | コマンドラインの `check` と同じ内容が表示されることを確認しました |
| 設定 | 項目の表示、条件付きの項目の出し分け、保存、不正な値を 7 種類拒否することを確認しました |
| 他のサイトからの要求 | 実際の画面をブラウザで開いて確認しました。画面からの操作は通り、合言葉のない要求、`text/plain` の POST、別の出所（`localhost` と `127.0.0.1` の違いを利用）から送った POST はすべて断られ、削除の処理まで届かないことを確認しました |
| 合言葉の渡し方と設定の保護 | 実際の画面で確認しました。`#t=…` のない URL では案内だけが表示され、API への通信は 1 件も行われませんでした。設定画面では場所やプログラムを指す 7 項目が読み取り専用で表示され、それ以外の設定は保存できました。正しい合言葉を使っても、`tool_dirs`・`steam_executable`・`steam_launch_options` は変更できませんでした。インストール先は、承認済みの場所（末尾に区切りを付けて入力しても同じ場所として扱う）は追加でき、承認されていない場所は断られ、一覧は変わりませんでした |
| HTTPS だけでの通信 | Ubuntu のコンテナで、実際の DLsite に対して確認しました。ログイン、購入一覧（208 件）、ダウンロード方法の解決に加え、実際のダウンロードのリダイレクト（`www.dlsite.com` → `download.dlsite.com`）もすべて HTTPS のまま通りました |
| シンボリックリンク | Ubuntu で確認しました。外を指すリンク（絶対パス・`../`・ディレクトリ・行き先の無いもの・リンクを経由するもの）は展開後に取り除かれ、中を指すリンクは残りました。DLC の重ね合わせと書き戻しでは、外を指すリンクを経由する場合に何も書かずに中止しました。「シンボリックリンクにする」で重ねた DLC は、書き戻すと本編が元の通常のファイルに戻り、DLC 側のファイルは変わりませんでした |
| 自動終了と接続の上限 | Ubuntu のコンテナで、本物の `serve` を使って確認しました（上限を 1 分にした使い捨ての設定）。合図を送り続けた 150 秒間は終了せず、何も送らない接続は 60 秒で切られ、合言葉のない要求だけを送り続けても、最後の合図から約 90 秒で自分で終了しました。画面では、終了後に「ツールは終了しています」と表示されました |
| DLC の取り消し | SteamDeck と Ubuntu で、Web UI と同じ経路で確認しました。2 回重ねても退避したファイルは 1 組のままで、書き戻すと元のファイルに戻ること、古い指定では操作できないことを確認しました |
