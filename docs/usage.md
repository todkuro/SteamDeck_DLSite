# 使い方

**通常の操作はすべて Web UI で完結する。** 端末が要るのは UI を起動する一手だけで、
SteamDeck ではそれもダブルクリック 1 回にできる。

## 起動

```bash
python3 -m dlsite_deck serve
```

ブラウザが開く。SteamDeck では同梱の `dlsite-deck.sh` に実行権限を付けておけば、
Desktop Mode でダブルクリックするだけで起動できる。

```bash
chmod +x ~/Applications/dlsite_deck/dlsite-deck.sh
```

終わるときは**画面右上の「終了」**を押す（サーバーごと畳む）。端末から起動した場合は
Ctrl-C でもよい。取得が走っている、または順番待ちが残っているときは**その件数を出して
確認を取る**（終了すると中断され、中途半端なファイルが残るため）。

## アプリケーションメニューに載せる（Desktop Mode）

Windows のスタートメニューにあたるのは、SteamDeck の Desktop Mode では**画面左下の
アプリケーションランチャー**。ここに載せるには `.desktop` ファイルをホーム配下に置く。
**`sudo` は不要で、OS の領域には触れない**（SteamOS の更新でも消えない）。

| 置き場所 | |
|---|---|
| `~/.local/share/applications/` | 自分だけのメニュー。**こちらを使う** |
| `/usr/share/applications/` | 全ユーザー共通。システム領域なので触らない |

同梱の `dlsite-deck.desktop` はパスが仮のままなので、書き換えてコピーする。
`~/Applications/dlsite_deck` に置いた場合:

```bash
chmod +x ~/Applications/dlsite_deck/dlsite-deck.sh
```

```bash
mkdir -p ~/.local/share/applications && sed -e "s|/path/to/dlsite_deck/dlsite-deck.sh|$HOME/Applications/dlsite_deck/dlsite-deck.sh|" -e "s|^Path=/path/to/dlsite_deck|Path=$HOME/Applications/dlsite_deck|" ~/Applications/dlsite_deck/dlsite-deck.desktop > ~/.local/share/applications/dlsite-deck.desktop
```

「ゲーム」と「ユーティリティ」の下に **DLsite for SteamDeck** が出る。すぐ出ないときは
メニューの索引を作り直す:

```bash
kbuildsycoca6 --noincremental
```

出てきた項目を右クリックすると、**タスクバーに固定**・**デスクトップに追加**・
**お気に入りに追加**も選べる。

- **`Exec` と `Path` は絶対パスでなければ動かない。** `~` は展開されないので、
  上のコマンドで `$HOME` を実際のパスに置き換えている
- **`Terminal=true` にしてある。** 起動すると端末の窓が一緒に開き、そこにログが出る。
  立ち上がらなかったときに理由が見えるようにするため。**その窓を閉じるとツールも止まる**。
  窓を出したくなければ `Terminal=false` に変えられるが、失敗しても何も表示されなくなる
  （終了は画面右上の「終了」から行えるので、どちらでも運用はできる）
- **初回だけ、先に端末から 1 回起動しておく。** 展開先がプロジェクトの外にある場合、
  書き込みの確認が出る（下の「ゲームモードから使う」と同じ理由）

```bash
cd ~/Applications/dlsite_deck && python3 -m dlsite_deck -y serve --no-browser
```

GUI だけで済ませたい場合は、ランチャーを右クリック →「アプリケーションの編集」で
メニューエディタからも同じことができる。ただし項目を手で埋める必要がある。

> **これはゲームモードへの登録とは別物。** メニュー登録が効くのは Desktop Mode だけで、
> ゲームモードから使うには次の手順が要る。

## ゲームモードから使う（Steam に登録する）

このツール自体を非 Steam ゲームとして登録すると、ゲームモードからも起動できる。

**先に一度だけ、端末から承認しておくこと。** 展開先がプロジェクトの外にある場合、
初回は書き込みの確認が出る。Steam やデスクトップから起動したときは端末が無く
確認に答えられないため、先に済ませておく必要がある（Web UI の設定を保存した場合も
承認したことになる）。

```bash
python3 -m dlsite_deck -y serve --no-browser
```

承認は `config.json` の `acknowledged_paths` に記録され、以後は聞かれない。

登録の手順:

1. Desktop Mode で Steam を開き、左下の「ゲームを追加」→「非 Steam ゲームを追加」
2. 「参照」でファイル形式を **すべてのファイル** に変えて `dlsite-deck.sh` を選ぶ
3. 追加したら**プロパティを開き、互換性の Proton は有効にしない**
   （Linux のシェルスクリプトなので Proton を通すと起動しない）

ゲームモードで起動すると Web UI が立ち上がり、既定のブラウザ（Flatpak 版 Firefox）が
開く。終了はゲームモードの「終了」から行う。

> ゲームモードは操作がタッチとコントローラに限られるため、細かい設定は
> Desktop Mode で行うほうが快適。

なお**コントローラ設定はこのツールから変更できない**。Steam の作りによる制限で、
ゲームモードで直接設定する必要がある。理由は [既知の制限 — コントローラ設定を扱えない理由](limitations.md#コントローラ設定を扱えない理由) を参照。

## 画面の構成

**ライブラリ** — 購入済み作品の一覧。

- カテゴリのプルダウンで表示を切り替える。既定は**ゲームのみ**で、マンガ・CG・
  ボイス・音楽・動画は選び直すと出る
- **Steam に登録済みかどうかが分かる。** 取得しただけの作品は「導入済み」と並べて
  **「Steam未登録」**が出る（ゲームのみ）。見出しにも未登録の件数を出すので、
  取得したまま登録し忘れているものに気付ける。
  判定は記録ではなく **`shortcuts.vdf` の実物**と突き合わせるので、Steam 側で
  直接削除した場合も追随する。Steam が見つからない環境では断定せず
  「登録状態不明」と出す
- **別環境（別 OS）の登録と区別する。** Steam はデバイス間で非 Steam ゲームの情報を
  見せることがある。exe のパス表記から**別のプラットフォームのものと確証が持てた
  エントリは、こちらの登録として数えない**。同じ名前のものが別環境にある作品は
  「別環境と重複」と表示し、**登録・解除のボタンを塞ぐ**（`shortcuts.vdf` の照合は
  名前で行うため、そのまま操作すると別環境の登録を書き換えてしまう）。
  判別できないパスは弾かない（自分の登録を取りこぼさないため）
- 状態（未取得 / 導入済み / 更新あり / 更新不明 / Steam未登録 / 別環境と重複）と
  タイトル・ID での絞り込み。
  **「更新不明」は更新の有無を判定できない作品**。DLsite が `upgrade_date` を
  返さない作品が多く（実ライブラリでは 4 割ほど）、これらを「導入済み」と
  だけ出すと、更新が無いのか分からないのかの区別が付かないため分けている
- **既定の並び**は「次にやること」の順。段の中はタイトル順:

  ```
  Steam未登録 → 更新あり → 未取得 → 登録済み・更新不明 → 記録のみ → 別環境と重複
  ```

  「別環境と重複」はこちらから触れないので最後に置く。
  下の「状態」順とは意図が違う（あちらは状態の重さ、こちらは次にやること）
- **並べ替え**（購入日 / タイトル / 更新日 / 状態 / サイズ、昇順・降順）。
  タイトル以外を選んだときは、同値の中をタイトル順で並べる。
  値が無いもの（更新日を返さない作品など）は、向きに関わらず末尾に置く。
  **状態順は「手を動かす必要がある順」**:

  ```
  更新あり → 別環境と重複 → Steam未登録 → 登録済み・更新不明 → 記録のみ → 未取得
  ```

  「更新不明」は判定できない作品では常にそう出るだけで対処のしようが無いため、
  「登録済み」と同じ段に置く（段の中はタイトル順なので互いに混ざって並ぶ）
- **インストール先**を一覧から選ぶ。設定した既定が最初から選択された状態になる
- 1 件ずつ、または表示中の未取得をまとめてダウンロード。
  **取得は同時に 1 本だけで、押した順に処理する**。まとめて押した分は順番待ちに
  積まれ、行に「順番待ち N」と出る。走り出す前なら「取り消し」でいつでも取り下げ
  られる。展開が終わるとアーカイブは自動で削除される
- **取得が終わった作品は、その場で表示が切り替わる**（「取得」→「Steam登録」など）。
  順番待ちが残っていても待たされない
- **進行状況は画面上部に貼り付く**（動いている 1 件だけ）。一覧を下へ辿っても見える。
  取得中の行のボタンは進捗表示に変わり、**中止**を押せる。
  中止するとダウンロード済みのファイルは削除される。
  展開は途中で安全に止められないため、その間の中止ボタンは押せない
- Steam 登録。実行ファイルが複数ある作品では**どれを登録するか選べる**。登録名は
  **DLsite のタイトルが初期値**で、その場で書き換えられる。解除もここから行う。
  候補は**サブディレクトリも含めて**列挙する（`InstallSet/InstallData/<本体>.exe`
  が本体、という形が実在する）。アンインストーラや設定ツール
  らしい名前・場所のものは「要注意」と表示して下位に置くが、**捨てはしない**
- **「記録のみ」は、記録はあるがフォルダが実在しない状態。** ツール外で消したか、
  **展開先が SD カードにあってマウントされていない**場合に起きる。後者では
  そこに置いた作品が一斉にこの状態になるので、取得し直す前にカードを確認すること。
  設定したインストール先・キャッシュが実在しないときは**画面上部に警告が出る**。
  その場所が `/run/media` 配下など取り外せる媒体に見えて、かつ「記録のみ」の
  作品がそこにある場合は、**SD カードが外れている可能性**も併せて知らせる
- **削除**。展開したファイルとダウンロードしたアーカイブを消し、記録からも外す。
  **Steam に登録済みのものは削除できない**（消すと起動できないショートカットだけが
  残るため、先に「解除」する）。実行前に、消える容量と、その作品を DLC として
  他の作品に適用済みなら**その相手**が示される（重ねたファイルは相手側に残る）。
  インストール先の外にあるものは、設定を書き換えても消さない

**Proton 設定** — 登録済みゲームの一覧と現在の Proton を表示し、行のプルダウンから
変更する。Steam の設定画面から変えるのと同じ効果。**Steam を終了してから操作すること**
（起動中は変更を受け付けない）。詳細は [CLI — Proton 設定タブ](cli.md#proton-設定タブ後から変更する) を参照。

## Steam 起動中の扱い

Steam は `config.vdf` と `shortcuts.vdf` を抱えたまま動き、**終了時に書き戻す**。
起動中に書き換えても捨てられるので、その間は次の操作を塞ぐ。

- Steam 登録 / 解除のボタン
- Proton 設定タブのプルダウン

塞いでいる間は画面上部に帯が出る。帯にはボタンが 2 つ並ぶ。

- **「Steam を終了する」** — Steam に終了を頼み、実際に落ちるまで待つ。
  `steam -shutdown` を使うので、Steam 自身が後片付けをしてから終わる
  （`pkill` で落とすと `shortcuts.vdf` を書き戻す前に死ぬことがある）。
  起動中のゲームがあれば先に終了しておくこと
- **「Steam を終了しました」** — 手で終了した場合に、実際のプロセスを見に行く。
  まだ動いていればその旨を表示して帯を残し、止まっていれば帯を消して操作を戻す

Steam 本体の場所は設定の **「Steam の実行ファイル」** で変えられる。既定は
SteamDeck の `/usr/bin/steam`。そこに無い環境では PATH と Steam のフォルダからも
探すので、たいていは既定のままでよい。

**ゲームモードでは Steam を終了できない。**（そのため上の 2 つのボタンも出さない） Steam 自身がセッションであり、
このツールもそこから起動されているため、終了すればツールごと落ちる。
つまりこれらの操作はゲームモードでは行えないので、
「終了してください」ではなく **「Desktop Mode に切り替えてください」** と案内し、
「Steam を終了しました」ボタンも出さない（押しても成立しないため）。

セッションの判別は動いているプロセスで行う。ゲームモードは `gamescope` が、
Desktop Mode は Plasma が受け持つ（実機の Desktop Mode で gamescope が動いて
いないことを確認済み）。

一覧を開いたまま Steam を起動していることもあるため、**ボタンを押した時点でも
必ずプロセスを確認する**。起動していれば処理を中断し、起動中の表示に切り替える。
（取得・展開・削除・DLC の重ね合わせは Steam に触らないので、起動中でも行える）

**状態・ログイン** — Cookie が読めているか、DLsite に繋がるか、分割 RAR の展開ツール、
pykakasi、Steam の起動状態と `userdata`、展開先の空き容量をまとめて表示する。
セッションが切れているときは、この画面にログイン手順がそのまま出る。

**設定** — `config.json` の項目を画面から編集して保存できる（設定 23 項目と、下記の操作ボタン 1 つ。設定のうち画面に出ないのは
`acknowledged_paths` だけで、これは承認したときに自動で記録される）。保存時に値の妥当性を
検証し、プロジェクト外のパスを指定した場合は警告を出す。

**保存ボタンの行は見出しのすぐ下に貼り付く。** 下までスクロールして設定したあと、
保存せずに他のタブへ移ってしまうのを防ぐため。見出しは画面幅が狭いと折り返して
高さが変わるので、実測して合わせている。

**未保存の変更があると知らせる。** 変更すると保存ボタンが
「保存（未保存の変更あり）」に変わり、枠が付く。その状態で他のタブへ移ろうとすると
確認が出る。**破棄して移ることもできる**（止めるのではなく選ばせる）。
タブを閉じる・再読み込みするときはブラウザ標準の確認が出る。

インストール先は複数登録できる。「インストール先の一覧」に 1 行 1 つで書き、
「既定のインストール先」でそのうちどれを既定にするかを選ぶ。既定はいつでも変更でき、
ライブラリ画面の選択欄に即座に反映される。ゲームごとに自由なディレクトリを掘る UI は
用意していない（ここで登録した場所からのみ選ぶ）。

アーカイブのキャッシュ置き場も「キャッシュ（アーカイブ置き場）」で変更できる。

**「カバーを作り直す」ボタン**がある。「カバーにタイトルを埋め込む」などを切り替えて
保存したあとに押すと、**登録し直さずに**登録済みゲームの画像を今の設定へ合わせ直す。
進み具合がボタンの横に出る。元の画像は作品フォルダに残してあるので、通常は
再ダウンロードしない。**Steam を起動し直すまで表示には反映されない**。
詳細は [CLI — カバーを作り直す](cli.md#カバーを作り直す) を参照。

待ち受けは既定で `127.0.0.1` のみ。ライブラリの内容は外に出ない。

> **`--host` で外部に開かないこと。** このツールに認証機構は無い。到達できる相手は
> 誰でも購入履歴を閲覧し、ダウンロードや Steam への登録を実行できる。
> 外部アドレスを指定した場合は起動時に警告を出す。

起動時にポートとプロセスを確認する。塞がっている場合は**理由を出して終了する**
（例外は投げない。終了コードは 1）。

| 状況 | 挙動 |
|---|---|
| 既にこのツールが同じポートで動いている | その URL を案内して終了 |
| 別のプログラムがポートを使っている | 別ポートの指定を促して終了 |
| 別ポートでこのツールが動いている | `state.json` が壊れうる旨を警告して続行 |

## ログイン

初回と、セッションが切れたときだけ必要。「状態・ログイン」タブに手順が出る。

1. Firefox で https://www.dlsite.com/ に通常どおりログイン（2FA 込み）
2. 続けて https://play.dlsite.com/ を**一度開く** — Play 側のセッションはここで確立される
3. Firefox は開いたままでよい。UI で「再確認」を押す

Play 側のセッションは短命ですぐ切れるが、ツールが実行のたびに自動で張り直すので
**ブラウザでの再ログインは基本的に不要**。張り直しにも認証情報や 2FA コードは使わない。

このツールはブラウザの Cookie データベースを読むだけで、ID・パスワード・2FA コードを
受け取ることも保存することもない。
